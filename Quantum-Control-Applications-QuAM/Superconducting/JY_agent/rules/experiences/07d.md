# 07d — readout frequency / duration / power optimization

## Lesson — 2026-09-29 18:54 Asia/Taipei: ten-qubit 07d crashes in measurement batching

- Device/project: `as-qpu-10qV2_agent`
- Workflow: `22f61b9119214d938354b11447c774ee`; lease `1d993a553cbb41efb42b3611503485d7`
- Run: `01b027b2fd17411e9c0da43eea488cf6`; no snapshot, no plot; 197 s; node
  defaults, all ten qubits multiplexed
- Failure: `KeyError: 'q6'` at `07d_Readout_Frequency_Duration_Power_Optimization.py:300`
  (`optimal_ds.sel(qubit=q.name)`), after the hardware finished. Lease paused as
  an unrecognized worker exception; state hash unchanged.
- Cause: `quam_libs/experiments/readout_optimization_3d/measurement_batching.py`,
  `_generate_balanced_subsets_indices`, slices `objects[i:i+S]` instead of
  `objects[i*S:(i+1)*S]`. With N=10 the MW-FEM demod limit gives S=2 and K=5, so
  the batches are indices [0,1],[1,2],[2,3],[3,4],[4,5]: q1, q10, q2, q3, q4, q5
  were measured and q6–q9 never were.
- Safe group sizes with the current code: N <= 4 (a single batch, S = N) and
  N = 5 (S=3, K=5, the overlapping slices wrap and cover every qubit). N = 6–10
  drop qubits.
- Recovery: re-run 07d in groups of at most four qubits (single batch). Only
  completed runs count toward single-pass, so a failed run does not block it.
  Alternatively fix the slice in `quam_libs` (operator decision; not changed).
- Do not copy this as an accepted setting.
