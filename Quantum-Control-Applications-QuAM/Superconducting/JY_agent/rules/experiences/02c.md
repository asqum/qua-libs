## Lesson — 2026-09-18 operator: 02c passes on dressed/bare separability alone

- Device/project: `as-qpu-10qV2_agent`
- Observation: the transition region around punch-out kept rejecting usable
  traces. Coverage, plateau width, depletion-point count, and monotonicity all
  judge the power segment where a point is neither clearly dressed nor clearly
  bare, which is exactly the segment the operator does not need.
- Recovery: 02c now passes when the dressed and the bare frequency can be told
  apart — separated by `min_frequency_separation_steps`, each observed on at
  least `min_classified_plateau_points` consecutive classifiable points, and
  neither on a frequency-sweep edge. The ambiguous middle is discarded. The
  proposed power is the highest power still classified as dressed and is not
  pushed to the last point before punch-out. Coverage, width, depletion points,
  and monotonicity are reported as `advisory_notes`; each has a `require_*`
  rule in `policies.yaml` to make it blocking again.
- 02c now fails only when dressed and bare remain inseparable after the
  frequency window has been widened to the 60 MHz policy limit and
  `num_averages` is at the 100 cap.
- Do not copy this as an accepted setting.

## Lesson — 2026-09-18 18:46 Asia/Taipei: 02c power limits must be integers

- Device/project: `as-qpu-10qV2_agent`
- Workflow: `0e9376e020b34de7a4899d87ed26c361`
- Run: `dca0e0f2dcb24d38a036d8b49b847f0f`; no snapshot, no plot
- Observation: requesting `min_power_dbm=-35.5` / `max_power_dbm=-25.5` to shift
  the power sampling grid by 0.5 dB crashed the worker during `initializing`.
  The protected node's Parameters model types both fields as `int`, so pydantic
  rejects any fractional dBm (`int_from_float`). JY's own policy schema reports
  them as `number` and does not catch this, and the crash is classified as
  `worker_failure`, which hard-stops the whole autonomy lease.
- Recovery: only use whole-number dBm limits for 02c. To resample the depletion
  region at a different power grid, change the integer window width or
  `num_power_points` (for example -36..-26 with 30 points vs -35..-25 with 30
  points), never a fractional endpoint.
- Do not copy this as an accepted setting.

## Lesson — 2026-09-18 19:50 Asia/Taipei: partial-pass multiplex runs cannot commit state

- Device/project: `as-qpu-10qV2_agent`
- Workflow: `0892399eba47422b96c9203e8ead1523`; lease `41aa462e64a94d1f8c569eb15139204a`
- Observation: the multiplex-first rule says to retry only the unresolved
  subgroup, so a 10-qubit node is resolved across several runs. But an
  autonomy lease only allows a state commit when the run's OVERALL
  `analysis_status` is `pass`. Every partial-pass 02c run is `needs_review`, so
  the qubits that did pass in that run can never have their
  `resonator/intermediate_frequency`, `readout/amplitude` and
  `extras/dressed_resonator_freq` committed under the lease — the server also
  refuses to remeasure an already-resolved target to obtain a clean all-pass
  run. In this workflow q10 (#140), q1/q2/q3/q6/q7/q9 (#141) and q4 (#142) all
  produced complete passing dressed-plateau evidence that stayed uncommitted.
- Recovery: raise with the JY maintainers. Either allow a lease commit of the
  per-target subset that passed inside a `needs_review` run, or fall back to an
  operator-approved `jy_request_state_commit` for the accumulated patches.
- Do not copy this as an accepted setting.
