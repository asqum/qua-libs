# AI client setup / AI 用戶端設定

所有用戶端都從 repository 最上層的 `jy_agent.ps1` 進入，再使用內層同一個
`start_mcp_stdio.ps1`，因此共用同一份
SQLite 稽核資料、hardware lock、policy 與 Dashboard。不同使用者應使用穩定且
可辨識的 `client_id`。

All clients enter through the same root `jy_agent.ps1`, which resolves the same
nested repository-owned launcher, and therefore share the same
audit database, hardware lock, policies, and Dashboard. Each operator should use
a stable, identifiable `client_id`.

| Client | Project config | Agent instructions |
| --- | --- | --- |
| Codex Desktop/CLI | root `.codex/config.toml` | root `AGENTS.md`, `.agents/skills/jy-qubit-bringup/` |
| Claude Code | root `.mcp.json` | root `CLAUDE.md`, `AGENTS.md` |
| Cursor Agent | root `.cursor/mcp.json` | root `.cursor/rules/jy-agent.mdc`, `AGENTS.md` |

首次開啟 project 時接受 MCP trust；之後不需手動開終端。若 client 顯示 MCP
unavailable，先確認開啟的是 repository 最上層、已接受一次性的 project trust，
再重新載入 project MCP。不需要切換到 `JY_agent` 子資料夾。不要把 MCP HTTP
port 暴露到公網。

Accept the project MCP trust prompt on first open. No user-operated terminal is
needed afterward. If MCP is unavailable, verify that the repository root is the
workspace, accept project trust, and reload project MCP. The nested `JY_agent`
folder need not be reopened. Never expose the MCP HTTP port publicly.

Project load and measurement entry are deliberately separate. Project load starts
only a clean STDIO MCP. The entry phrase makes the agent run root `Ensure`, which
starts the local HTTP services and public Dashboard before the corresponding
entry tool. See [`debugQA.md`](../debugQA.md) when the tool catalog is missing or
an `initialize response` fails.

各平台的實際 bootstrap 行為：

- Codex／ChatGPT Desktop、Codex CLI 與 Codex IDE 讀取 trusted repository root 的
  host-local `.codex/config.toml`（由 `jy_agent.ps1 -Action Install` 依
  `.codex/config.toml.example` 產生）；`required=false` 避免 JY MCP 初始化失敗時阻斷一般專案工作；
  沒有成功取得 `jy_enter_*` 回傳時仍不得宣稱已進入量測模式。
- Claude Code 讀取 repository root `.mcp.json`，`${CLAUDE_PROJECT_DIR:-.}` 讓 launcher
  不依賴使用者從哪個 working directory 啟動；project MCP 第一次仍會要求信任。
- Cursor IDE／CLI 讀取 repository root `.cursor/mcp.json`，並由 always-applied rule 將兩個
  入口語句（含省略空格與英文別名）以及接續語句 `繼續JY自動量測模式` 導向
  `jy_bringup`。第一次同樣需接受 project MCP。

Actual bootstrap behavior by client:

- Codex/ChatGPT Desktop, Codex CLI, and the Codex IDE read the trusted project's
  host-local `.codex/config.toml`, generated by `jy_agent.ps1 -Action Install`
  from `.codex/config.toml.example`. `required=false` keeps ordinary repository work available;
  measurement entry still requires a successful `jy_enter_*` result.
- Claude Code reads the root `.mcp.json`; `${CLAUDE_PROJECT_DIR:-.}` makes the
  launcher independent of the shell's starting directory. Project MCP trust is
  still required once.
- Cursor IDE/CLI reads `.cursor/mcp.json`; the always-applied project rule maps
  both entry phrases (with or without spaces, plus their English aliases) and
  the continue phrase `繼續JY自動量測模式` to `jy_bringup`. It also requires
  one-time trust.

`Ensure = ready` only reports the HTTP/Dashboard infrastructure. It does not add
an MCP server to an already-created conversation. If that conversation's tool
catalog lacks `jy_bringup`, run root `jy_agent.ps1 -Action Doctor`, then
enable/trust the project server and reload or create a new Agent session.

安裝驗證可由使用者在 repository root 執行 `jy_agent.ps1 -Action Install`，或
直接要求尚未載入 JY MCP 的 coding agent 執行同一支 script；正常量測則只需
輸入入口語句。這刻意把「一次安裝」與
「每次執行」分開，避免用自然語言假裝能建立一個尚不存在的 MCP。

Installation validation can be run by the operator or by an ordinary coding
agent asked to execute root `jy_agent.ps1 -Action Install`. Normal measurement
then needs only an entry phrase. Separating one-time installation from each run is the honest boundary:
natural language cannot invoke an MCP server before the client has discovered it.

網頁版聊天產品若沒有本機 project/MCP host，不能單獨啟動這套工具。手機應 remote
回本機既有的 agent 對話，並用公開 Dashboard 做核准、看圖與停止。

A browser-only chat product without a local project/MCP host cannot start these
tools. A phone should remote into the existing desktop-agent conversation and
use the public Dashboard for approval, plots, and stop controls.
